# My Postico プロダクト仕様書

- ステータス: Draft
- 対象リリース: MVP
- 最終更新: 2026-09-14

## 1. 概要

My Postico は、個人利用を目的とした macOS 向け PostgreSQL GUI クライアントである。
日常的なデータベース操作に必要な機能へ絞り、軽量で分かりやすく、安全にデータを閲覧・編集できることを目指す。
特に、SQL を手書きせずに複雑な検索条件を組み立てられるフィルター機能を中核価値とする。

### 1.1 目的

- PostgreSQL のテーブルやデータを GUI で素早く確認する
- 複数条件のフィルターを GUI で直感的に作成、保存、再利用する
- SSH トンネル経由で、外部へ直接公開されていない PostgreSQL に安全に接続する
- SQL を直接記述・実行し、結果を表形式で確認する
- データの追加・更新・削除を安全に行う
- 接続先やよく使う SQL をローカルで管理する
- 将来的に AI による SQL 作成支援を追加できる構造にする

### 1.2 MVPで扱わないもの

- PostgreSQL 以外のデータベース
- チーム共有、クラウド同期、ユーザーアカウント
- データベースサーバーの管理・監視
- ER 図の編集
- AI 機能
- プラグイン機構

## 2. 想定利用者

PostgreSQL を利用する開発者本人。ローカル環境、開発環境、ステージング環境を中心に利用し、必要に応じて本番環境へ読み取り専用で接続する。

## 3. 基本方針

- macOS 専用のデスクトップアプリとして開始する
- PostgreSQL 専用として設計する
- 高機能なデータフィルターを最優先の P0 機能として実装する
- SSH トンネル接続を MVP の P0 機能として実装する
- DB パスワードは平文ファイルへ保存しない
- 破壊的操作は対象と影響を明示してから実行する
- 大量データを一括取得せず、ページングまたは取得件数制限を用いる
- SQL 実行結果とエラーを隠さず表示する

## 4. MVP機能要件

### 4.1 接続管理

ユーザーは PostgreSQL 接続を作成、編集、複製、削除できる。

接続設定:

- 表示名
- ホスト
- ポート（初期値: 5432）
- データベース名
- ユーザー名
- パスワード
- SSL モード
- 環境区分: Local / Development / Staging / Production
- 読み取り専用設定
- SSH トンネルの使用有無

要件:

- 保存前に接続テストを実行できる
- パスワードは macOS Keychain に保存する
- パスワード以外の設定はアプリのローカル領域に保存する
- 接続失敗時は PostgreSQL のエラー内容と再確認項目を表示する
- Production 接続は色とラベルで常時識別できる

#### SSHトンネル（P0・必須）

PostgreSQL へ直接接続できない環境向けに、SSH 踏み台サーバーを経由したローカルポートフォワーディングを提供する。

SSH 接続設定:

- SSH ホスト
- SSH ポート（初期値: 22）
- SSH ユーザー名
- 認証方式: パスワード / 秘密鍵 / SSH Agent
- SSH パスワード
- 秘密鍵ファイル
- 秘密鍵のパスフレーズ

要件:

- PostgreSQL の接続設定と SSH 接続設定を分離して表示する
- 保存前に SSH トンネルを含む PostgreSQL 接続テストを実行できる
- SSH 接続後、動的に割り当てたローカルポートから PostgreSQL へ接続する
- SSH パスワードと秘密鍵パスフレーズは macOS Keychain に保存する
- 秘密鍵の内容をアプリ内へ複製保存しない
- SSH ホスト鍵を検証し、未知または変更された鍵を無条件に許可しない
- 初回接続ではホスト名、鍵種別、フィンガープリントを表示してユーザーの確認を求める
- 確認済みホスト鍵はアプリのローカル領域へ保存する
- ホスト鍵が変更された場合は接続を拒否し、明確な警告を表示する
- 接続中は SSH トンネルの状態をメイン画面へ表示する
- SSH または PostgreSQL の切断を識別して表示する
- アプリ終了、DB 切断、接続切り替え時にトンネルと関連リソースを解放する
- SSH 接続処理によって UI をブロックしない
- タイムアウトとキャンセルに対応する
- MVP では単一の SSH 踏み台サーバーを対象とし、多段 SSH は扱わない

### 4.2 オブジェクトブラウザー

接続中のデータベースについて、以下をツリー表示する。

- スキーマ
- テーブル
- ビュー
- カラム
- インデックス
- 制約

操作:

- 展開時に必要な情報を遅延取得する
- 名前による絞り込みができる
- オブジェクト名を SQL エディタへ挿入できる
- テーブルを選ぶとデータ画面または構造画面を開く

### 4.3 テーブル構造の表示

選択したテーブルについて以下を表示する。

- カラム名
- データ型
- NULL 許可
- デフォルト値
- 主キー
- 外部キー
- インデックス

MVP では構造変更を行わず、読み取り専用とする。

### 4.4 テーブルデータの閲覧

- データをグリッド形式で表示する
- 初期取得件数は 100 件とする
- 次ページ・前ページへ移動できる
- カラム単位で昇順・降順に並べ替えられる
- 条件を指定して絞り込める
- NULL と空文字を視覚的に区別する
- JSON / JSONB は整形表示できる
- 長い値は省略表示し、詳細表示で全体を確認できる
- バイナリ値は直接展開せず、型とサイズを表示する

### 4.5 高機能フィルター（P0・必須）

テーブルデータの閲覧時に、SQL を手書きせず検索条件を作成できる。MVP のリリース判定に必須とし、簡易的な文字列検索だけで代替しない。

#### 条件ビルダー

- 「カラム」「演算子」「値」の組み合わせで条件を追加できる
- 複数条件を `AND` または `OR` で結合できる
- 条件の追加、複製、削除、有効化・無効化ができる
- 条件の並べ替えができる
- 条件グループをネストし、`(A AND B) OR C` のような条件を表現できる
- 現在適用中の条件数を常時表示する
- フィルターを一括解除できる

#### 対応演算子

カラムのデータ型に応じて、利用可能な演算子だけを表示する。

- 共通: `=`、`!=`、`IS NULL`、`IS NOT NULL`
- 文字列: `contains`、`not contains`、`starts with`、`ends with`、`LIKE`、`ILIKE`
- 数値・日時: `>`、`>=`、`<`、`<=`、`BETWEEN`
- 真偽値: `is true`、`is false`
- 列挙・選択可能な値: `IN`、`NOT IN`
- 配列・JSON/JSONB: MVP では等価、NULL 判定、および PostgreSQL の包含演算に対応する

#### 値の入力

- データ型に合った入力 UI を表示する
- 日付・日時には日付入力を使用する
- boolean は true / false を選択する
- `IN` / `NOT IN` は複数値を入力できる
- NULL 判定では値入力欄を表示しない
- 不正な値は DB へ送信する前に表示し、適用を拒否する
- 入力値は SQL へ直接連結せず、必ずパラメーターとして渡す

#### 適用と結果表示

- フィルターはユーザーが「適用」した時点で実行する
- Enter キーでも適用できる
- 適用中は進捗を表示し、キャンセルできる
- フィルター変更後は先頭ページへ戻る
- フィルターと並べ替えは同時に利用できる
- 該当件数を取得可能な場合は表示し、重い件数取得はキャンセルまたは省略できる
- 適用中の条件を、人が読める形式と SQL プレビューの両方で確認できる
- SQL プレビューは表示専用とし、実際の値はパラメーター化されていることを示す

#### 保存と再利用

- テーブルごとにフィルターへ名前を付けて保存できる
- 保存済みフィルターを一覧から適用できる
- 保存済みフィルターの名前変更、上書き、複製、削除ができる
- 最後に適用したフィルターを、同じテーブルを再度開いたときに復元できる
- 存在しないカラムや変更された型を参照する保存済みフィルターは実行せず、修正が必要な条件を表示する

#### クイックフィルター

- 選択セルのコンテキストメニューから「この値と等しい」「この値と異なる」「この値を含む」を追加できる
- カラムヘッダーから、そのカラムを対象とする条件を追加できる
- クイックフィルターも条件ビルダー上に表示し、後から編集できる

### 4.6 データ編集

- セルの値を編集できる
- 新規行を追加できる
- 選択した行を削除できる
- 未保存の変更を明示する
- 保存前に変更内容を確認できる
- 複数の変更は原則として単一トランザクションで保存する
- 保存失敗時はロールバックし、エラー対象を表示する
- 読み取り専用接続では編集操作を無効化する

更新対象の特定:

- 主キーがあるテーブルは主キーを使用する
- 主キーがない場合、MVP では更新・削除を無効化する
- 更新件数が想定を超えた場合はロールバックする

削除時の確認内容:

- 対象テーブル
- 対象行数
- 行を識別する主キー値
- 実行される操作が取り消せない可能性

### 4.7 SQLエディタ

- 複数タブを開ける
- SQL のシンタックスハイライトを行う
- 選択範囲がある場合は選択範囲のみ実行する
- 選択範囲がない場合は現在のステートメントを実行する
- キーボードショートカットで実行できる
- 実行中のクエリをキャンセルできる
- 実行時間と取得行数を表示する
- 複数結果セットを切り替えて表示できる
- PostgreSQL エラーのメッセージと位置情報を表示する
- 実行結果を CSV で書き出せる
- 名前を付けた SQL は接続設定ごとに分離してローカル保存する
- 保存済み SQL はフォルダを作成して分類・移動できる
- Queriesペインで新しいSQLファイルを追加した時点で保存項目を作成し、フォルダ上から追加した場合はそのフォルダへ所属させる
- オブジェクトサイドバーを Queries / Tables の上下ペインに分け、保存済み SQL とテーブルを同時に参照できる
- Queries / Tables の境界はドラッグして高さを変更できる

破壊的 SQL:

- `DROP`、`TRUNCATE` および条件なしの `UPDATE` / `DELETE` を検出する
- 検出時は警告し、明示的な確認後に実行する
- 読み取り専用接続では書き込み SQL を実行しない

### 4.8 履歴とお気に入り

- 実行した SQL、実行日時、接続先、成功・失敗、所要時間を保存する
- 履歴から SQL エディタへ復元できる
- SQL に名前を付けてお気に入り保存できる
- パスワードや接続文字列などの機密情報を履歴へ保存しない

### 4.9 CSVエクスポート

- SQL・テーブルの表示結果を CSV または JSON で macOS のダウンロードフォルダへ保存できる
- 同名ファイルがある場合は連番を付け、既存ファイルを上書きしない
- 表示結果をヘッダー付きTSVとしてコピーし、表計算ソフトへ直接貼り付けられる
- クリップボード用文字列の過大生成を避けるため、20,000セルまたは概算5MBを超える結果は表コピーを無効化する

- テーブル表示結果または SQL 実行結果を CSV として保存できる
- UTF-8、ヘッダーありを初期値とする
- エクスポート対象が現在のページのみか全件かを明示する
- 全件出力はストリーミング処理し、メモリへ全件保持しない

## 5. 画面構成

### 5.1 接続一覧画面

- 保存済み接続一覧
- 新規接続ボタン
- 接続設定の編集・複製・削除
- 接続状態と環境区分の表示

### 5.2 メイン画面

- 上部: 接続名、データベース名、環境区分、読み取り専用状態
- 左側: オブジェクトブラウザー
- 中央: テーブルデータ、構造、SQL エディタのタブ領域
- 下部: 実行結果、メッセージ、エラー
- ステータス領域: 接続状態、実行中状態、トランザクション状態

### 5.3 主要な操作フロー

#### 接続

1. 接続一覧から接続先を選ぶ
2. Keychain から認証情報を取得する
3. PostgreSQL へ接続する
4. メイン画面を開き、スキーマ一覧を読み込む

#### データ編集

1. テーブルを選択する
2. 行またはセルを編集する
3. 変更内容を確認する
4. トランザクションを開始して変更する
5. 成功時はコミット、失敗時はロールバックする

#### SQL実行

1. SQL を入力する
2. 実行対象を決定する
3. 危険な SQL を検査する
4. SQL を実行する
5. 結果またはエラーを表示し、履歴へ記録する

## 6. セキュリティ要件

- DB パスワードは macOS Keychain にのみ保存する
- SSH パスワードと秘密鍵パスフレーズは macOS Keychain にのみ保存する
- SSH 秘密鍵の内容をログまたはアプリ設定へ保存しない
- SSH ホスト鍵を検証し、鍵変更時は自動接続しない
- ログへパスワード、接続文字列、完全な認証エラーを出力しない
- Production 接続では初期値を読み取り専用にできる
- 読み取り専用は UI 制御だけでなく、可能な限り DB セッション側でも適用する
- SQL 履歴は端末内にのみ保存する
- クラッシュレポートへ SQL や取得データを含めない
- クリップボードへのコピーはユーザー操作時のみ行う

## 7. 非機能要件

### 7.1 パフォーマンス

- 通常の画面操作に対して即時に反応する
- DB 通信中も UI をブロックしない
- SSH 接続とトンネル処理中も UI をブロックしない
- 取得結果が大きい場合も仮想スクロールを使用する
- クエリキャンセル操作を常に利用できるようにする

### 7.2 信頼性

- 接続切断を検知し、再接続手段を表示する
- SSH トンネルの切断を検知し、DB 接続と整合する形で再接続手段を表示する
- アプリ終了前に未保存の編集と実行中クエリを確認する
- 予期しない終了後に未保存の SQL タブを復元できる

### 7.3 アクセシビリティ

- キーボードのみで主要操作を実行できる
- 色だけに依存せず環境区分や状態を表示する
- macOS のライト・ダークモードへ対応する

## 8. 技術構成（案）

- デスクトップ基盤: Tauri
- UI: React + TypeScript
- ビルド: Vite
- PostgreSQL 接続: Rust の PostgreSQL クライアント
- SSH トンネル: Rust の SSH クライアントライブラリによるローカルポートフォワーディング
- ローカル設定: Tauri のアプリデータ領域
- 認証情報: macOS Keychain
- SQL エディタ: Monaco Editor または CodeMirror
- UI 状態管理: 小規模な状態管理ライブラリまたは React 標準機能
- テスト: Rust 単体テスト、TypeScript 単体テスト、主要操作の E2E テスト

実装開始前に、採用ライブラリの Tauri 対応状況、ライセンス、メンテナンス状況を確認する。

## 9. データ保存方針

ローカルには次の情報を保存する。

- 接続設定（パスワードを除く）
- SQL 実行履歴
- お気に入り SQL
- 保存済みフィルターとテーブルごとの最終フィルター
- SQL タブの復元情報
- UI 設定

保存データにはスキーマバージョンを持たせ、将来のマイグレーションに対応する。

## 10. MVP受け入れ条件

- 保存済み接続から PostgreSQL へ接続できる
- パスワード、秘密鍵、SSH Agent の各認証方式で SSH トンネルを確立できる
- SSH トンネル経由で PostgreSQL へ接続し、通常接続と同じ操作を実行できる
- 未知の SSH ホスト鍵は確認なしに信頼されない
- 保存済み SSH ホスト鍵が変更された場合は接続が拒否される
- SSH パスワードと秘密鍵パスフレーズが平文の設定ファイルへ保存されない
- 接続終了時に SSH トンネルとローカル待受ポートが解放される
- パスワードが平文の設定ファイルへ保存されない
- スキーマ、テーブル、カラムを閲覧できる
- 100 件単位でテーブルデータを閲覧できる
- GUI から単一条件および複数条件のフィルターを作成できる
- `AND` / `OR` とネストした条件グループを組み合わせて適用できる
- カラム型に応じた演算子と入力 UI が表示される
- フィルター値がパラメーター化され、SQL インジェクションを起こさない
- フィルターと並べ替えを併用してもページング結果が一貫する
- フィルターへ名前を付けて保存し、再起動後も再利用できる
- セルまたはカラムヘッダーからクイックフィルターを追加できる
- 無効な保存済みフィルターを安全に検出し、DB へ送信しない
- 主キーのあるテーブルで追加・更新・削除ができる
- 編集の失敗時にトランザクションがロールバックされる
- SQL を実行し、結果またはエラーを確認できる
- 実行中のクエリをキャンセルできる
- 結果を CSV へ出力できる
- 読み取り専用接続では書き込み操作が拒否される
- Production 接続が常時識別できる
- アプリ再起動後に保存済み接続と未保存 SQL を復元できる

## 14. 実装上の注意

- SQL を文字列連結して更新クエリを組み立てず、値は必ずパラメーター化する
- 識別子は PostgreSQL の規則に従って安全にクォートする
- ページングは単純な OFFSET 方式から開始できるが、大量データ向けに keyset pagination を検討する
- SQL の安全判定だけをセキュリティ境界にしない
- 読み取り専用ユーザーの利用を推奨し、アプリ側の制御と併用する
- 自動コミットと明示的トランザクションの状態を UI で判別できるようにする
